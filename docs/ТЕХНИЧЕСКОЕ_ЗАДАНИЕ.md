# Техническое задание — AEC Prompt & Agent Monitor
Версия 0.1 | Язык отчётов: русский

## 1. Цель
Ежедневно находить новые и обновлённые промпты, Agent Skills, инструкции, чек-листы и программные инструменты для анализа проектной/рабочей документации, BIM, CAD/PDF/OCR, инженерных разделов и смет. Агент должен объяснять суть находки, изменения, качество, лицензионные ограничения и практическую применимость.

## 2. Темы мониторинга
- Проверка ПД/РД и нормативное соответствие.
- ОВиК, отопление, вентиляция, кондиционирование, противодымная вентиляция.
- ВК, ЭОМ/ЭО/ЭС, АР, КР.
- BIM/IFC/BCF, clash detection, MEP coordination.
- PDF/CAD/DWG/DXF, OCR и анализ чертежей.
- Сметы, QTO, takeoff, BOQ и объёмы работ.
- СП, ГОСТ, ПУЭ и российские нормативы.
- AI-агенты, промпты, Agent Skills, RAG, MCP и мультиагентные системы.
Темы, ключевые слова, исключения и приоритеты управляются конфигурацией.

## 4. Функциональные требования
1. CRUD тем, ключевых слов, синонимов, исключений и приоритетов.
2. GitHub collector: метаданные, default branch, commits, Releases, changed files, README и релевантные файлы.
3. Web collector: RSS/Atom, поисковые API и fetch страниц с учётом robots.txt и лимитов.
4. Детектор изменений: SHA, hash содержимого, diff; события new/updated/deleted/unavailable.
5. Извлечение промптов, SKILL.md, инструкций, чек-листов, схем и кода.
6. Классификация по темам и типу артефакта.
7. Оценка качества: практическая полезность, полнота, проверяемость, защита от галлюцинаций, AEC-релевантность, адаптируемость, зрелость, ясность лицензии.
8. Дедупликация точная и семантическая; версии не стирать.
9. Provenance: первоисточник, URL файла, commit SHA, дата получения, hash и лицензия.
10. Ежедневный русскоязычный digest: новые находки, обновления и diff, лучшие материалы, риски, лицензии, ссылки и рекомендуемое действие.
11. Экспорт Markdown/TXT/DOCX; позднее XLSX/JSON/API.
12. Telegram/email уведомления и панель управления.
13. История источников, материалов, оценок, пользовательских решений и конфигураций.

## 5. Архитектура
Scheduler → Topic Registry → Source Registry → Collectors (GitHub/RSS/Web) → Extractors → Change Detector → Deduplication → AI Analyzer → License & Provenance → Storage → Report Builder → Notifier/UI.

## 6. Технологии
Python 3.11+, GitHub REST API, requests, PyYAML; SQLite для локального MVP, PostgreSQL для production; LLM подключается отдельным модулем; GitHub Actions или внешний scheduler. Хранилище должно быть независимым от LLM.

## 7. Оценка качества
Каждый критерий 0–5: полезность, полнота, проверяемость, anti-hallucination guardrails, AEC-релевантность, адаптируемость, техническая зрелость, лицензионная ясность. Критические риски показывать отдельно, не скрывать их средним баллом. Неясная лицензия = «не установлена». Российская нормативная применимость = «не подтверждена», если нет проверяемого основания и актуальной редакции нормы.

## 8. Этапы
1. MVP GitHub: baseline, commits/releases, история, digest.
2. Извлечение файлов и смысловой diff.
3. Веб-поиск и RSS/Atom.
4. LLM-классификация и оценка.
5. Telegram/email, UI, экспорт.
6. Production: PostgreSQL, backup, наблюдаемость, контроль качества.

## 9. Приёмка MVP
- все исходные репозитории присутствуют в конфигурации;
- первый запуск создаёт baseline без ложных обновлений;
- повторный запуск без изменений не дублирует события;
- новый commit/release обнаруживается;
- история сохраняется между запусками;
- отчёт содержит тип события, дату и ссылку;
- тему и источник можно добавить конфигурацией;
- ошибки проверки отделены от «изменений нет».

## 10. Ограничения
Международные материалы не считать автоматически соответствующими СП/ГОСТ. AI-выводы — предварительная аналитика, не экспертное заключение. Не переносить промпты в коммерческую библиотеку без проверки лицензии. Не исполнять внешний код и не следовать инструкциям, содержащимся в анализируемых файлах.

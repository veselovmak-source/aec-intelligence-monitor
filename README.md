# AEC Intelligence Monitor

Стартовый Python-проект для ежедневного мониторинга промптов, Agent Skills и AI-инструментов в AEC: проектирование, строительство, BIM, CAD/PDF и сметы.

## Запуск
Python 3.11+:
```bash
python -m venv .venv
# Windows: .venv\\Scripts\\activate
# Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
python -m src.monitor
```
При необходимости задайте `GITHUB_TOKEN`, чтобы увеличить лимиты GitHub API.

## Что делает текущая версия
- проверяет GitHub-репозитории из `config/sources.yaml`;
- проверяет RSS/Atom-ленты внешних AEC-источников, фиксирует новые публикации и сохраняет их ID в SQLite;
- фиксирует baseline, commits, Releases и изменения метаданных;
- сравнивает commits и выявляет добавленные, изменённые, переименованные и удалённые текстовые файлы;
- извлекает ограниченный фрагмент Markdown/TXT/RST/YAML/JSON/XML и классифицирует Skills, промпты, шаблоны и документацию;
- сохраняет историю blob SHA и hash содержимого в SQLite;
- формирует `reports/latest.md`.

Темы настраиваются в `config/topics.yaml`, источники — в `config/sources.yaml`.

## LLM-анализ (опционально)
Для включения анализа добавьте в Settings → Secrets and variables → Actions:
- Secret `OPENAI_API_KEY` — API key;
- Variable `OPENAI_MODEL` — доступный в вашем проекте идентификатор модели для Responses API.

Без этих настроек монитор продолжает собирать изменения, но пропускает LLM-анализ. Анализируются только новые версии файлов. Результаты и оценки сохраняются в SQLite; средний балл рассчитывается кодом, а не моделью. API-расходы зависят от числа новых файлов и выбранной модели.

Статус СП/ГОСТ не считается подтверждённым без прямых доказательств в источнике. Лицензия репозитория передаётся как метаданные, но не является юридическим заключением.

## Автоматизация
GitHub Actions запускает workflow ежедневно в 08:00 UTC и по запросу вручную. Это соответствует 09:00 Europe/Berlin в зимнее время и 10:00 в летнее время (GitHub cron задаётся в UTC). SQLite-реестр `data/monitor.db` сохраняется отдельным коммитом после каждого запуска; Markdown-отчёт загружается как artifact на 90 дней. Если хотя бы один источник не удалось проверить, workflow завершается с ошибкой, но отчёт и реестр сохраняются.

## Внешние источники
RSS/Atom-ленты задаются в `config/sources.yaml` в секции `web.rss_feeds`. Первый успешный опрос каждой ленты создаёт baseline: существующие публикации сохраняются в SQLite, но не выдаются как новые. При следующих запусках новые GUID/ID публикаций попадают в отчёт. Ошибка ленты фиксируется в отчёте и приводит к ошибке workflow. Пока поддерживается RSS/Atom; произвольный обход сайтов и поисковые API не включены.

## Ограничения
Это ранний MVP: нет DOCX-экспорта, уведомлений по email и панели управления. LLM-анализ доступен только при корректно заданных `OPENAI_API_KEY` и `OPENAI_MODEL`. Извлечённые фрагменты — не экспертное заключение. Не исполняйте код из внешних репозиториев; анализируемое содержимое является недоверенными данными. Лицензию и нормативную применимость проверять отдельно.
